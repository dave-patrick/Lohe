# Lohe: project context

## Overview
Native Android podcast client using Kotlin, Jetpack Compose, Room, and a debug MCP/REST surface.

## Library mirrors
- Android Auto projection uses `PlaybackService`'s `MediaLibrarySession` and `MediaLibrary` browse tree for Continue listening, Up Next, Downloads, Shows, Playlists, and episode/show search. AAOS additionally uses `CarPlaybackService` and `CarHomeScreen`, registering the same platform media-session token so car and phone share playback state. The media service declares the launcher icon, and the car media card uses a monochrome tintable attribution vector.
- The Playlists tab has six derived smart playlists: Played, In Progress, Unplayed, Not Downloaded, Downloaded, and New Releases (last seven days). They update from episode state, default to visible, and each visibility preference persists in DataStore.
- Room schema 12 adds per-podcast auto-queue preferences and whether newly discovered episodes go at the head or tail of Up Next. Schema 11 adds a separate `playedAt` completion timestamp, preserved through refresh. Schema 10 retained unsubscribed podcast rows using `isSubscribed`; normal subscription lists, search, counts, and feed refresh exclude those rows without deleting their episodes or history.
- Playlist TSV column 11 stores the optional snapshot flag and column 12 stores the optional pinned flag. Missing values preserve legacy behavior. A snapshot resolves its explicit ordered IDs while honoring the played and archived filters; completed episodes are removed from it. Marking played removes explicit playlist membership centrally; archiving follows the configurable delay (24 hours by default). Reopening clears both completion time and archive state.
- EpisodeMaintenance checks due completion times in process and through a persisted 15-minute Android job. Android may defer background execution. Archiving cancels active downloads and removes local copies; failed cleanup is retried. Archived episodes with actual listened time remain in Home's listening signal, while archives with no recorded listening do not inflate it. Original shared-storage audio sources are not deleted.
- One-time Pocket Casts mirrors are explicit snapshots, not recurring synchronization. Keep credentials and operational exports outside the repository and back up device data before replacement or APK installation.

## Current feature additions

- Podcast detail exposes Unsubscribe beneath its description, outside episode selection. Confirming uses the existing repository unsubscribe/history behavior, then returns to the previous screen. EpisodesViewModel owns the in-flight request and its lifecycle-aware outcome state; duplicate requests are ignored, cancellation is propagated, and failures remain on the page with retry feedback.

- Manual in-app playback switches capture and save the interrupted item's live position before persisting it at the head of Up Next and replacing media on the shared player. Save explicitly even when already paused; a second pause emits no event. Queue auto-download checks read only the requested episodes and do not block the switch. Media-session play requests resolve only the selected episode and its show, rather than reading every show.
- Resume positions are supplied by `onSetMediaItems` before preparation, and by the service when advancing Up Next. Never restore position with a delayed seek after `STATE_READY`; that plays the beginning and can overwrite stored progress. Explicit pauses save progress immediately in addition to the periodic saves.
- Player-screen episode selections are consumed once; the active session is authoritative after queue advancement. Finishing with no next episode or an end-of-episode sleep timer clears the completed player item. Media session seek buttons use the saved skip intervals.
- Up Next owns automatic advancement: the media session removes the repeat-mode command while preserving default controller trust/library access, and the service resets non-off repeat modes defensively. A single-item player must reach STATE_ENDED instead of looping behind the queue. Queue renumbering updates existing members only, so a stale drag/order snapshot cannot reinsert an episode already dequeued on completion. Explicit enqueue can still request a replay.
- Room schema 13 adds `archivedAt` so completed episodes can remain in Played for a configurable retention window before their downloaded copy is removed. Manual archive marks the episode played and clears its queue position. Older archived rows without this timestamp are preserved by cleanup.
- Podcast Updates uses WorkManager for configurable periodic feed refresh (default six hours; Never cancels it). Custom playlists can follow selected shows and exclude individual episodes; opted-in auto-download playlists download newly discovered matching episodes. Separate explicit podcast assignments on any custom playlist include nondeleted, nonarchived episodes from those podcasts that match the playlist played-status filter, except individual exclusions; legacy show/folder rules and snapshots remain restorable. Assigned episodes resolve dynamically and do not backfill downloads.
- Each podcast's episode screen exposes Automatically add to Up Next with Beginning/End placement. Enabling there adds existing unplayed, nonarchived, nondeleted episodes that are not already queued, then the shared setting adds newly discovered episodes during future refreshes. Placement can be chosen before enabling. Disabling leaves existing queue entries alone, and selection hides these controls. Discover's explicitly new-episodes toggle retains its future-only behavior; both screens share the saved future-queue setting.
- Each fresh podcast episode view starts on Unplayed immediately, including previously visited shows with legacy saved filters. Filter choices (All, Played, Unplayed, Listening, Downloaded, Starred, Archived) remain local to that visit; saved sort order remains independent per podcast in SettingsStore. EpisodesViewModelFactory injects the store; isolated fixtures may omit it for local sorting state. Existing saved filter keys remain readable for compatibility but do not override the view's opening default.

## Existing guidance

- Room schema 14 repairs legacy unplayed rows with positive resume points: positions meeting playback's 95 percent or final 10 seconds completion rule become played and leave Up Next; other positive positions become in progress. The repair preserves listening totals, downloads, and other library metadata. Repository progress imports use the same completion thresholds as playback so near-complete imports cannot linger as unfinished entries; completion preserves newly learned duration in a transaction.

- Playlist detail uses one scrolling list for its compact header, Podcasts assignment row, playback controls, and episodes. Episode row taps open notes without playing; the row Play button and notes-sheet Play button explicitly start playback. Selection-mode taps still select. Notes load their full description on demand. Every playlist open defaults to unplayed, with a compact filter icon and Show all recovery when no episodes match. Detail Play/Up Next actions use the visible subset. Secondary actions live in the three-dot menu. Selection actions remain pinned while episodes scroll; the themed podcast assignment dialog provides artwork, selected highlights, search, and a selected count. Its changes remain local until Save.
- Swipe action trays across podcast cards, episodes, playlists, and Up Next share `SwipeActionsHost`: Cancel, an outside tap, or Back closes the tray without applying the action. Outside taps are consumed so they cannot also play another episode. Only one tray stays open. Episode swipes reveal controls and require tapping an action to commit. Podcast episode cards reserve vertical drags for list scrolling; tapping a card opens its details/notes sheet while selection taps select. The explicit Play button and notes-sheet Play action start playback.
- List dragging tracks the carried item by its stable lazy-list key and reorders during stationary edge holds. Preserve the numeric viewport when swapping its first visible slot, and wait for the moved layout before scrolling again; move eligibility keeps pinned groups and reserved headers intact, and release/cancel stops the scroll.
- Inside custom and smart playlists, episode swipes reveal Up Next on the right swipe and Archive on the left swipe, each with Cancel. Archive is unavailable for already archived rows, and selection mode disables both swipe directions. Up Next right-swipe trays include Top and End queue moves alongside one-position moves; Cancel stays visible and overflow actions scroll horizontally. Moves use current database membership and never start playback.
- Playlist detail saves an independent episode sort per playlist in SettingsStore: Manual, File size, Length, Publish date, or Podcast title, with ascending/descending direction. Unknown values sort last in either direction. Computed sorting changes displayed and batch Play/Up Next order without overwriting manual episode IDs; manual drag controls and persistence are disabled while a computed sort is selected.
- Android 12+ launch uses `values-v31/Theme.Lohe` with a transparent system splash icon and black background. The full branded splash is rendered by Compose; do not let Android fall back to the masked launcher icon before it.
- A single settings button is anchored by LoheNavHost at the top-right of primary tabs and episode screens; local headers reserve a 48 dp slot instead of positioning their own gears. Settings is a category index with separate Appearance, Playback, Floating player, Archiving, and Downloads routes, plus the existing About destination. Subpage Back returns to the index. Keep the debug BUG affordance below the shared header.
- Floating player size choices are 48, 56 (default), 72, and 88 dp, preserving 48 dp minimum touch targets. Transparency is 0–75% (window alpha 1–0.25). Changes apply live and persist in DataStore; size changes re-clamp the normalized saved position.
- Cross-app floating controls are optional and off by default. FloatingPlaybackService owns a small TYPE_APPLICATION_OVERLAY window and a dismissible specialUse foreground-service notification. Start it only from a resumed activity after user-granted overlay permission; no accessibility service or automatic permission grants. Positions and collapsed state persist, seek amounts follow playback settings, and hiding the overlay does not stop audio. Battery setup is optional and opens system settings rather than requesting a direct power exemption. The onboarding wizard is planned in docs/TODO.md, not implemented.
- Playlist cards keep pinned custom playlists at the top across sort modes. Grid cards expose a drag grip in the space below the artwork; list cards place the grip at the far left in Manual sort. Reordering saves through PlaylistRepository and preserves hidden folder slots. Grid episode totals use bold electric blue numerals.
- Cross-app floating playback uses only FloatingPlaybackService; do not show a second in-app floating control when the overlay is disabled. The mini-player stays above the bottom bar with a visible accent glow. Its Play/Pause disc is 47.25 dp with a 28 dp glyph in a 48 dp touch target, preserving the 64 dp row minimum.

## Conventions

- Dense icon actions reserve at least 48 dp in layout; do not force a 48 dp child into a smaller wrapper. Podcast episode and playlist actions wrap below metadata/header content with FlowRow so targets remain separate on narrow screens.

- Google Play phone/tablet builds use `-PlohePlayStore=true`; the high-priority `src/play/AndroidManifest.xml` removes car-specific declarations only from Release and the isolated, minified/non-debuggable `smokeRelease` package (`com.lohe.app.releaseaudit`). Ordinary Release and private Debug preserve the car implementation. Never upload the smoke APK or Debug APK to Play. CI without signing credentials emits an explicitly unsigned AAB plus its R8 mapping.
- About exposes an offline privacy-policy dialog. `docs/privacy-policy.md` is the source for `app/src/main/assets/privacy-policy.txt` and `docs/privacy/index.html`; regenerate with `tools/prepare-privacy-policy.ps1` and verify with `-Check`. Pages stages index/guide/assets/privacy, not internal planning documents. Publishing is separate from local preparation.
- Settings and the player button share `rememberFloatingPlayerPermissionFlow`: overlay rationale/special access first, then optional notification rationale on Android 13+, with denial/Not now allowing controls and audio. A persisted handled flag avoids repeated OS notification prompts; Settings links to Android notification settings. Never launch permission dialogs automatically at startup.

## Security and performance boundaries

- Screen flows use lifecycle-aware Compose collection so stopped activities do not retain library queries. QueueViewModel resolves playlists only while subscribed; explicit batch queue actions take a fresh one-shot resolution. Legacy completed-membership reconciliation runs once, while current completion cleanup remains centralized in SubscriptionRepository.onPlayed. Preserve five-second progress persistence without permanently observing the full episode library.

- PlaybackService initializes ServiceLocator before constructing its session or launching observers. Android can start the media service in a fresh process without MainActivity. Run PlaybackColdStartTest alone in the isolated .audit process to validate this path; ordinary playback fixtures initialize dependencies and cannot cover it.

- Release CarAppService connections use AndroidX host signature validation and its standard allow-list; permissive hosts are restricted to debug builds. Media3's trusted/read-only controller defaults remain in use.
- Feed bodies are limited to 16 MiB, catalog responses to 4 MiB, and artwork to 8 MiB of actual decoded response data. Feed, catalog, artwork, and download clients share a base OkHttp pool; feeds and short requests have total call deadlines while downloads retain a longer idle read timeout.
- Artwork uses a 64 MiB disk LRU with atomic cache writes and at most four simultaneous loads. Bounds decoding remains intentional.
- Local diagnostics are off by default in release settings. Enabling Diagnostics exposes the BUG button and permits local recording. URLs are redacted, event writes use a bounded background channel and buffered rotating writer, at most five report folders are retained, and release reports never capture logcat. Nothing is uploaded by reporting.
- Both backup formats exclude diagnostics and re-downloadable episode files while preserving library/preferences backups. Keep RECEIVE_BOOT_COMPLETED for persisted archive jobs; SAF imports require no broad storage permission.
- The debug REST/MCP API authenticates headers before body reads using an installation-specific random token in noBackupFilesDir/debug-api-token. See docs/MCP.md for private local retrieval and request limits. MCP GET returns 405 because server notifications are unsupported.
- Feed persistence runs inside a database transaction, batches history and episode reads below SQLite bind limits, and skips unchanged episode writes. Maintenance pages due IDs; show-card counts use a database aggregate. Search treats LIKE wildcards literally.
- Transport controls update from player events while idle; position updates remain periodic during playback. The sleep timer waits for its deadline; the overlay updates play state from events and checks permission separately.
- For isolated device testing, pass -PloheDebugApplicationIdSuffix=.audit. This installs a separate debug package and must not replace or clear the user's com.lohe.app data.
- CI pins action revisions, runs lint, reviews dependency changes, and configures weekly Dependabot updates. Release shrinking relies on upstream Room/Media3 rules rather than blanket keeps.

- The shared episode notes sheet shows a localized full publishing date, duration, and file size when positive metadata is available. Podcast, playlist, and player entry points supply stored metadata; the player retains its current-media ID guard.
- Episode details expose Play, Up Next, and Archive as icon-only controls with accessible action labels and 48 dp targets. Archive appears on podcast, playlist, Up Next, and player entry points unless already archived. Navigation clears matching active/deferred playback and pending UI selection before the existing archive operation; archiving another episode leaves current playback alone. The player returns to its previous screen after archiving.
- PlaybackService supports Media3 resumption and a dedicated recent-media browse root, with the standard MediaButtonReceiver. PlaybackResumptionStore records the last actually playing ID, including continuous transitions. Resume positions remain in Room and are supplied before preparation. Queue edits preserve lastPlayedAt. Legacy fallback reads only the latest row with playback state; older versions mixed queue edits into that timestamp, so their exact last-playing identity can be ambiguous until the first playback on this version. Stored missing/deleted/archived/finished IDs do not fall back to a different episode. Browsing/connecting alone never starts audio. Real Android Auto last-app selection and reconnect autoplay still require a head-unit check.
- Up Next row taps open the shared episode notes sheet without changing queue order or starting playback. Its explicit Play controls promote the episode before playback; selection taps still toggle selection.
- Playlist and Up Next episode rows emphasize duration values in bold ElectricBlue, including remaining and total time for partially played episodes; other metadata stays muted.
- Podcast, playlist-detail, and Up Next episode titles show a passive queue-membership indicator from existing Room state. Appearance settings persist its visibility, dot/ring/queue-icon style, blue/teal/amber color, and 8/12/16 dp size with a live preview. Defaults are an enabled small blue dot; disabling retains design choices. Navigation passes settings once per screen, with no per-row collectors or extra membership queries.

- Show notes render feed HTML through Compose AnnotatedString.fromHtml, preserving formatting and tappable accent-colored underlined links. Plain-text descriptions retain their original line breaks. Feed ingestion retains episode anchors and up to 128,000 characters of rich notes, including nested XHTML; podcast summary blurbs stay plain text.
